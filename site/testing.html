01 / Tooling

vanilla-test owns the suite and coverage command

vanilla-test@2.1.0 is node-cmd’s only direct development dependency. Its dependency graph contains only the author’s ansi-colors-es6 and strong-type modules. The shipped package declares no runtime dependencies, and npm does not install the test tool for node-cmd consumers.

{
  "scripts": {
    "test": "node ./test/node.mjs",
    "coverage": "vanilla-test coverage node",
    "verify": "npm test && npm run coverage && npm run test:package && npm run site:check"
  },
  "devDependencies": {
    "vanilla-test": "2.1.0"
  }
}

The suite uses VanillaTest for case lifecycle and reporting. Node’s built-in node:assert/strict supplies precise deep equality, rejection, and pattern assertions; no separate assertion framework is installed.

02 / Coverage contract

Per-file native Node coverage gates

vanilla-test coverage node executes the same suite under native V8 coverage and publishes text, HTML, LCOV, and JSON summary reports. Both shipped entry points are included.

03 / Behavior inventory

What the 17 tests prove

  1. CommonJS surface: classic exports plus every v6 method and alias.
  2. ESM surface: default and named exports resolve to the same implementations.
  3. Shell callback: stdout, stderr, callback contract, and immediate process access.
  4. Shell options: cwd, environment, encoding, and callback overload compatibility.
  5. Live shell streams: run() works without a callback and exposes output.
  6. Interactive stdin: data can be written through the returned child process.
  7. Promise success: output shape and promise.child behavior.
  8. Promise failure: exit code, stdout, and stderr stay attached to rejection.
  9. Cancellation: AbortSignal reaches the Node execution primitive.
  10. Synchronous contract: stable envelope, options, buffers, and failure capture.
  11. Sync validation: invalid input returns the original error instead of cascading.
  12. Sync stderr isolation: captured child stderr does not leak to the parent.
  13. Literal arguments: shell metacharacters remain data in direct-file calls.
  14. Direct callback overloads: args, options, omitted args, and stream access.
  15. Direct Promises: success, failure, options, omitted args, and process handle.
  16. Direct sync: success, buffers, omitted args, and failure envelope.
  17. Unbuffered spawn: args/options overloads and writable stdin for runStream.

06 / Failure policy

Any failed case or gate stops delivery

vanilla-test returns a structured result with ok and failureCount; the Node adapter maps it to the process exit code. Coverage thresholds, package smoke, and site validation also return nonzero on failure. GitHub Pages only assembles and deploys after tests, coverage, and package verification have all passed.
