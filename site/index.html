The familiar API, expanded

Small surface. Full process control.

Version 6 keeps the calls existing applications rely on and adds the explicit execution paths modern code expects.

01 / COMPATIBLE

Your classic calls still read the same.

Keep using run(command, callback) and runSync(command). Add options only when the command needs a different directory, environment, timeout, or cancellation signal.

run(command, options?, callback?)→ ChildProcess

02 / PROMISES

Await the result.

runPromise and its compatible runPromisified alias resolve with separate stdout and stderr values.

{stdout,stderr}

03 / DIRECT

Skip the shell, keep the result.

Use buffered runFile, runFileSync, or runFilePromise to execute a file with an explicit argument array and capture its output.

gitstatus--short

04 / CONTROL

The process is not hidden.

Process-returning calls expose Node’s ChildProcess. Read its PID, pipe its streams, write to stdin, listen for events, or stop it with kill().

05 / OPTIONS

Execution context is explicit.

Set cwd, extend or replace env, bound work with timeout, and cancel cooperatively with an AbortSignal.

06 / STREAM

High output should not wait for a buffer.

runStream(file, args?, options?) uses Node’s built-in spawn and returns an unbuffered ChildProcess for long-running, high-output, and interactive programs.

stdinprocessstdout / stderr

CommonJS + ESM + promises

Choose the calling style, not a toolchain.

No transpiler, bundler, or TypeScript runtime is required.

// CommonJS · callback remains optional
const cmd = require('node-cmd');

const child = cmd.run(
    'git status --short',
    { cwd: './project' },
    (error, stdout, stderr) => {
        console.log(stdout);
    }
);

console.log(child.pid);
// Native ES module · unbuffered ChildProcess
import cmd from 'node-cmd';

const child = cmd.runStream(
    'git',
    ['status', '--short'],
    { cwd: './project' }
);

child.stdout.pipe(process.stdout);
// Promise API · stdout and stderr stay separate
import { runPromise } from 'node-cmd';

const { stdout, stderr } = await runPromise(
    'npm test',
    {
        cwd: './project',
        timeout: 30_000
    }
);

console.log(stdout);

A deliberate execution matrix

Shell, direct, async, or sync.

Pick one dimension at a time. The method name tells reviewers exactly how a command starts and how its result arrives.

run(command, options?, callback?)classic + extended

Runs a command through the platform shell. The options and callback are both optional. The returned ChildProcess is available immediately.

runPromise(command, options?)also runPromisified

Resolves after the command finishes with {stdout, stderr}. Use the alias when preserving existing promisified call sites.

runFile(file, args?, options?, callback?)direct execution

Runs an executable without shell parsing and buffers its output. Its Promise and sync companions make buffered direct execution available in every calling style.

runStream(file, args?, options?)unbuffered spawn

Uses built-in spawn and returns the live ChildProcess. Use it for interactive tools, long-running services, and output that should flow immediately.

Choose the execution boundary

Strings speak shell. Arrays speak process.

A shell command is the right tool for pipes, redirects, variable expansion, and chained commands. Direct execution is the clearer boundary when a program and its arguments are already known. Choose buffered runFile for a final result or unbuffered runStream for a live process.

Important: node-cmd does not sanitize commands or reduce operating-system privileges. Never concatenate untrusted input into a shell string.

Read the security guidance →
Shell string
run('git status | tee status.txt')
  • Shell operators are interpreted
  • Best for deliberate shell composition
  • Untrusted text must not be concatenated
Direct file + args
runFile('git', ['status', '--short'])
  • No shell operator parsing
  • Program and arguments stay separate
  • Preferred for structured invocation
